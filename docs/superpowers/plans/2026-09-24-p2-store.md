# dsh-prompt-enhancer P2：可测试的 SQLite 存储层 实施计划

> **面向 Agent 执行者：** 必需子技能：使用 superpower-subagent-driven-development（推荐）或 superpower-executing-plans 按任务逐项执行，逐任务评审。步骤使用复选框（`- [ ]`）语法跟踪。

**目标：** 交付 **M2**——一个**可脱离宿主单测**的存储层：4 张表 + 全部存储函数 + `node --test` 全绿（含负样本）。

**架构：** `src/host/store.ts` 是**纯模块**（零宿主依赖、零 cordis import），惰性单例连接 `node:sqlite` 的 `DatabaseSync`。db 路径在**每次调用时**从 `process.env.DSH_HOME` 解析，因此测试只需在自己的进程里把 `DSH_HOME` 指向临时目录——**生产代码不导出任何 test-only API**（`node --test` 一个测试文件一个进程，天然隔离）。测试文件直接 `import` `.ts` 源码（Node 24 类型擦除），故 `src/**` 必须是可擦除 TS，且相对导入写显式 `.ts` 扩展名。

**技术栈：** Node ≥ 22.19（实测 v24.19.0）、`node:sqlite`、TypeScript 5.9（仅类型检查，`noEmit`）、Node 内置 `node --test`（**无第三方 runner**）、esbuild（沿用 P1 契约）。

**规格：** `docs/superpowers/specs/2026-09-24-dsh-prompt-enhancer-design.md`（**已定稿，权威**）。执行前必须读：§4.1（schema 与初始化顺序）、§4.2（设置项）、§4.3（导入导出格式）、§4.4（可回滚与统计语义）、§5（路由表 → 反推存储函数面）、§9.1（测试覆盖）、§12（风险表）。

## 全局约束

1. **路径**一律项目根相对 + 正斜杠；所有命令默认**以项目根为当前工作目录**；宿主侧路径用 `$DSH_HOME` 表达，不写死盘符或用户目录。
2. **npm 一律带 `--cache .npm-cache`**（缓存落工作区外会被沙箱拒绝）。
3. **不引入 `js-yaml`**；**P2 完全不读写 `settings.yaml`**（设置持久化的落点在 P3，见「交接给 P3」）。
4. **`src/` 内部相对导入必须写显式 `.ts` 扩展名**（如 `import { dbPath } from "./paths.ts"`）。实测：Node 直跑 TS 不做 `.js`→`.ts` 重映射；esbuild 与 tsc（需 `allowImportingTsExtensions`）都接受 `.ts`。
5. **`src/**` 必须是「可擦除 TS」**：不得使用 `enum`、`namespace`、参数属性、构造函数参数属性等需要代码生成的语法。由 tsconfig 的 `erasableSyntaxOnly` 在编译期强制（实测 `enum` 报 TS1294）。
6. **`src/host/store.ts` 不得 import 宿主/服务**（cordis、webServer、llm、settings…）：它必须能脱离宿主单测。任何需要宿主能力的东西（设置读写、AI、路由）都在其它模块。
7. **只修改本计划列出的文件**；不得改动 `.tmp/dsh-prompt-library/`（只读上游参考）。
8. **测试不得削弱**：不允许为了变绿而删除/跳过断言；负样本必须真实失败过（先红灯）。
9. Shell：本机为 **macOS（bash）**；若抄用上游/旧文档里的 PowerShell 写法，按等价 bash 执行。

## 设计决策（含与上游/初稿的偏离，执行时不得偏离）

| # | 决策 | 理由 |
| --- | --- | --- |
| **P2-D1** | db 路径 seam = `paths.dbPath()` **每次调用**从 `process.env.DSH_HOME` 解析；**不导出任何 test-only API**（无 `resetDb`/`closeDb`） | 测试隔离靠「一文件一进程 + 临时 `DSH_HOME`」；生产代码不留测试痕迹。上游 `paths.ts` 本就是调用期函数，零额外成本 |
| **P2-D2** | **设置持久化不进 P2**；`enforceMaxCount(maxCount)` 由调用方传上限 | 规格 §4.2 要求写 `settings.yaml`、§6.5 又禁用 `js-yaml`，两条只有「用宿主 `settings` 服务」能同时满足，而那是**装配期**决策（需 `ctx.inject(['settings'])` + schemastery peer dep）。store 保持纯模块，上限由参数注入 |
| **P2-D3** | 淘汰策略按**规格 §4.4**：`aiRefined = 0` 优先，其次 `lastUsedAt` 最旧 | 上游是 `usageCount` 升序再 `updatedAt`；规格已明确覆盖之，**不得**照抄上游 |
| **P2-D4** | 播种只写**中文**欢迎提示词，不读 `locale.preference` | 读 locale 要解析 `settings.yaml`，会把 YAML 依赖拖进 P2（违反约束 3） |
| **P2-D5** | **无迁移**：v1 的 DDL 即终态；只留 `meta.schemaVersion` + 一个恒为空的、**被 await** 的迁移钩子数组，顺序在建表之后、播种之前 | 规格 §4.3 明确不做旧库/旧 JSON 自动迁移（老用户走「旧插件导出 → 新插件导入」）。上游「迁移 fire-and-forget + 播种在前」的顺序缺陷由此**在结构上不可能发生** |
| **P2-D6** | `tags` 列恒存 `'[]'`（规格 DDL 为 `NOT NULL DEFAULT '[]'`），空数组不存 NULL | 上游空数组存 NULL，读侧需额外兜底；NOT NULL 更安全且省一层分支 |
| **P2-D7** | 软删除写入 `trash` 时**不带** `skillName` / `skillExportedAt`（规格 trash DDL 无这两列） | 遵循规格 DDL；代价与后续处理见「风险 R3」 |
| **P2-D8** | `ensureTag` 改为**接收当前连接 `cur` 的私有辅助**，公开 `ensureTag(name)` 只做入口 | 规格 §12 明确要求修上游「`ensureTag` → `getDb()` → 播种/syncTags → `ensureTag`」的无限递归，且必须单测覆盖 |
| **P2-D9** | `listPrompts(options)` 在 store 内完成 `q` 搜索 / `tag` 过滤 / `sort` 排序，路由层只做信封 | 规格 §5 的 `GET /prompts?q&tag&sort` 需要它；放 store 才可单测。`sort` 取值定义：`default`（三段式：7 天内新建 → 使用量前 3 → updatedAt 降序）/ `updated` / `used` / `created` |
| **P2-D10** | 删除 `usage_log` 与 `pl_prompt_versions` 两张表 | 规格 §4.1 的 4 表 DDL 即权威；上游这两表分别「只写不读」与「只写不读且无路由」 |
| **P2-D11** | **全部存储函数同步**（不返回 Promise） | `node:sqlite` 本身是同步 API；上游之所以 async，只因它 `await` settings 与迁移。同步化让测试与路由更简单，并消灭「忘了 await」这一类 bug（P2-D2 已把 settings 移出 store） |
| **P2-D12** | `updatePrompt(id, patch, options?: { aiWriteBack?: boolean })`：**只有显式传 `aiWriteBack: true` 且 `sourceBody` 为空时**，才回填 `sourceBody ← 旧 body` 并置 `aiRefined = 1` | 规格 §4.4 说的是「**AI 结果**写回 body」；store 无法自己分辨 AI 写回与用户手工编辑，必须由调用方声明，否则用户改一个错别字就会被误标成「AI 优化稿」 |

**N5 的方法论备注（值得记住）**：该用例的「未超限不删」由**两处**共同保证（`if (all.length <= maxCount) return []` 早退 + `slice(0, 全量-上限)` 的算术），任一单点改动都不改变行为，因此单点变异无法触发它——必须组合变异。这属于**用例过强于单点变异**，不是用例失效。

**过程中的两个真实教训**：

1. **变异测试的脚本自身会骗人**：第一轮把 N4 标为「未被捕获」，实际是脚本固定跑 `tests/store.test.mjs`，而 N4 用例在 `formats.test.mjs` 里——「匹配 0 个用例」被误当成「用例抓不到缺陷」。若当时直接采信，会得出完全错误的结论。
2. **类型细节（P3 写 bind 时会遇到同类问题）**：`StatementSync.run(...)` 不接受 `unknown[]` 展开（须 `string | number | null`）；`run().changes` 的类型是 `number | bigint`，参与数值比较前必须 `Number(...)`。
